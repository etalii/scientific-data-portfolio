# Skill design and invocation evaluation

Five entrypoints were checked with the skill-creator quick validator. Relative
links point to central durable references/templates; no copies of the methodology
are embedded in each skill. This is schema/manual boundary evaluation, not an
independent agent execution study or proof of implicit discovery in every client.

| Responsibility | Decision | Evidence / stable I/O |
|---|---|---|
| Authority mapping | KEEP AS REFERENCE/TEMPLATE | Both pilots reference pre-existing authorities; map template plus existing contract-first skill |
| Evidence assembly | CREATE SKILL, combined evidence-review | Both pilots map actual commands/outputs to evidence |
| Claim-support review | CREATE SKILL, same evidence-review | Both retain qualified claims and unsupported/overstrong alternatives |
| Narrative design | CREATE SKILL, combined story-design | Both require ordered claims and explicit caveats |
| Visual decision/specification | CREATE SKILL, same story-design | Visual dengue and nonvisual climate justify two branches |
| Human packet generation | CREATE SKILL | Both reduce multiple requirements to attributed grouped decisions |
| Lifecycle coordination | KEEP IN ORCHESTRATOR | Shared dependency/gate responsibility; router only dispatches |

## Manual routing cases and expected observable outputs

| Request | Applicable responsibility | Required output / exclusion |
|---|---|---|
| Reconstruct a completed descriptive study | lifecycle -> evidence-review | retrospective origins, preserved history, no invented preregistration |
| Start a new bounded unit inside an active project | lifecycle | explicit unit/cutover and pre-execution gate; old results labeled prior knowledge |
| Which task is next with valid draft claims? | lifecycle | pending exact human requirements; not automatic delivery |
| Register observations from existing validators | evidence-review | command/input/output references separate from claim interpretation |
| Two files share a grid; can we claim direct comparability? | evidence-review + domain comparability | split geometric support from domain applicability; no generic threshold |
| The audit has no useful map | story-design | explicit not_required rationale and human review, no decorative visual |
| Figure alt wording differs from specification | story-design | declared literal/semantic/editorial policy and actual review, no automatic equivalence |
| Human approved only two of three items | human-review | per-item dispositions and unresolved closure gate preserved |
| Apply the edits already explicitly approved | human-review | exact new revisions/provenance; no repeated permission request |
| Rename a local plotting variable | none | avoid unsolicited lifecycle/skills work |
| Deploy a certified report | retained publication skill | no analytical recomputation or automatic science approval |

No skill writes approvals from advisory classifications. No skill grants external
messaging, publishing, Git commit or push permissions. Domain semantics remain
in project authorities. New skills may need a fresh session for discovery; the
repository paths are available for explicit invocation now.
