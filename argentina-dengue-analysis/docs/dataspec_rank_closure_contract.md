# Retrospective rank pilot closure contract

Contract ID: `dataspec_rank_closure`. Version: `1.0.0`.

## Authority, scope and ownership

The requesting human explicitly accepted H01–H05 and H07/H09, and accepted
H06/H08 conditional on the exact supplied editorial changes. The preserved
`human_decision_request.txt` is the decision source; `human_decisions.yml` is its
structured transcription. `requesting_user`, with `review_mode: self`, is a
role identifier, not an inferred personal identity or independent peer review.
Present application timestamps do not claim to recover historical review dates.

The new project-local producer `23_close_dataspec_rank_pilot.R` owns the immutable
configured closure directory. It consumes the original bundle/audit, current
configuration, preserved pre-closure configuration, decision source/transcription,
accepted QMD source, and original governed analytical inputs. It calls the existing
C.16 reproduction and C.20 rank/PNG audit helpers without changing them.

The original report, QMD, PNG, v1 audit and bundle remain historical evidence.
The final deliverable is a new standalone selected HTML section, generated by
extracting the archived section, applying exactly the approved introduction and
alt text, and appending the preserved limitations. This is a canonical fragment
revision, not a complete Quarto render or a replacement of the published report.
The accepted QMD preserves the original dynamic value expressions and carries
the same approved text. Other report sections are outside acceptance.

## Integrity and lifecycle

All 117 baseline identities remain protected by the original audit policy.
Only the nested DataSpec configuration extension changes the operational config;
its pre-closure bytes are preserved. Original v1 records retain their exact bytes
in the archived bundle; validate that snapshot against the pre-closure config.

The current candidate bundle retains unchanged question/plan/contracts/metrics
at revision 1 and creates revision 2 for changed execution/evidence/claims/specs/
delivery. It is a new candidate snapshot, not an overwrite of the earlier one.
The original accepted automated review stays in the historical snapshot; a new
automated review ID records closure checks. Two additional human review records
cover the nine exact-revision requirements and the explicitly authorized
conditional delivery acceptance. The delivery review points to delivery;
delivery must not point back to it and create a cycle. Expected current count:
20 records. Historical drafts remain available through the archived bundle hash.

Accepted claims remain qualified. Narrative, visual and delivery use the existing
`accepted` status; `delivery_disposition` remains `qualified_answer`. Question,
plan and evidence do not acquire invented human acceptance. All common validator
`certified` fields remain false: bounded project acceptance is not universal
scientific certification or independent peer review.

## Required checks

- Run the existing 21 mechanical controls against the approved fragment and
  accepted source, preserving the original analytical input identities.
- Reproduce all six C.16 outputs exactly, reconcile the 24 denominators/rates,
  geography and ranks, and reproduce the unchanged 2400×1800 PNG byte-for-byte.
- Assert literal approved introduction, alt and spec caption; preserve every
  supplied limitation and original analytical claims. No geometry change occurs.
- Preserve the original metadata, verify original validation has only its nine
  historical REVIEW findings using its preserved config, and validate the new
  complete bundle with no findings. Never modify common schemas or validators.
- Fault injection must show that absent human review blocks delivery, altered
  approved text is rejected, and changed evidence hashes stale consumers.
- A read-only `--check` reruns reproduction, compares all immutable closure file
  hashes, repeats the editorial/trace checks, and publishes no new metadata.

## Publication and Git policy

The producer builds in isolated sibling staging, validates before atomic directory
rename, refuses overwrite, and removes only its own temporary workspace. Initial
failure publishes no closure. Configuration paths come from `config/project.yml`.

The closure directory's JSON files are explicitly version-controlled provenance:
`audit.json`, `checks.json`, `environment.json`, `baseline.json`, `bundle.json`,
`validation.json`, `mutation_checks.json`, and `acceptance.json`. Its
`baseline_project.yml` is the unchanged historical configuration snapshot.
`report_fragment.html` is an explicit curated presentation deliverable exception,
not a versioned analytical dataset. The study's `pre_closure_project.yml` is also
version-controlled historical provenance, never a second operational config.
No raw data, processed indicators, scratch outputs or unrelated files are tracked.

Acceptance metadata retains each original disposition, whether editorial revision
was required and applied, the review scope, human-source hash, old/new report
identities with exact authorized cause, unchanged PNG identity, actual application
time and validator limitations. Generated JSON is written only by this producer.
