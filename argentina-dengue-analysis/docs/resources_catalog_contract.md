# Resources Catalog Contract

## Contract identity

- **Contract ID:** `resources_catalog`
- **Version:** `2.0.0`
- **Artifact:** `data/metadata/resources_catalog.csv`
- **Producer:** `scripts/acquisition/00_fetch_metadata.R`
- **Primary consumer:** `scripts/acquisition/01_download_data.R`

## Purpose

`resources_catalog.csv` is the project's internal inventory of the resources
published for the configured dataset. It is not a copy of a CKAN API response.

The contract isolates downstream stages from CKAN response details. Changes to
the CKAN response structure must be handled only by the metadata-acquisition
script, provided that the contract remains compatible.

## Scope and invariants

- The catalog contains every resource discovered in the CKAN dataset response.
- It contains only the fields defined in this contract and in the documented
  column order.
- It is generated by code and must not be edited manually.
- `resource_id` is unique and identifies one source resource per row.
- The catalog is sorted by `resource_id` to produce a deterministic inventory.
- Required source metadata must be present for every resource; otherwise the
  producer fails without writing a partial catalog.
- Nullable fields are represented as empty CSV fields.
- Source timestamps preserve the non-empty CKAN value after surrounding
  whitespace is removed. The catalog does not infer or add a timezone.

## Schema

| Column | Type | Required | Origin | Consumer and purpose |
| --- | --- | --- | --- | --- |
| `resource_id` | string | Yes | CKAN resource `id` | Download, validation and logs; stable source identifier. |
| `resource_name` | string | No | CKAN resource `name` | Human-readable auditing and logs. It is never used as an identifier. |
| `resource_description` | string | No | CKAN resource `description` | Human-readable auditing of the resource inventory. |
| `resource_format` | string | Yes | CKAN resource `format`, normalized to uppercase | Resource selection and deterministic local filename generation. |
| `download_url` | string | Yes | CKAN resource `url` | Input URL for `01_download_data.R`. |
| `local_filename` | string | Yes | Generated by the project | Target filename for raw-data download; derived deterministically from `resource_id` and the URL extension, with a documented format fallback. |
| `source_created_at` | source timestamp string | No | CKAN resource `created` | Source provenance and audit; preserved without timezone inference. |
| `source_last_modified_at` | source timestamp string | No | CKAN resource `last_modified` | Source provenance and future update detection; preserved without timezone inference. |
| `source_resource_state` | string | No | CKAN resource `state`, normalized to lowercase | Resource-selection policy and audit. |
| `eligible_for_download` | boolean | Yes | Generated by the project | Indicates technical eligibility for `01_download_data.R`; it does not express epidemiological or analytical precedence. |
| `eligibility_reason` | string | Yes | Generated by the project | Explains the deterministic technical eligibility outcome for audit and diagnostics. |

## Excluded fields

- `source_dataset_id` is excluded because this catalog is scoped to the single
  dataset defined in `config/project.yml`.
- `year` is excluded because the project must not infer semantic properties
  from CKAN resource names or descriptions.
- `notes` is excluded because an unstructured field has no explicit pipeline
  consumer or stable semantics.
- A provider checksum is excluded until its algorithm and validation contract
  are defined explicitly.

## Local filename policy

`local_filename` uses the following policy:

```text
{resource_id}.{sanitized_extension_from_download_url}
```

The producer removes a query string and fragment from `download_url`, obtains
the final filename extension in its path and accepts it only when it is
alphanumeric. The extension is normalized to lowercase before it is used.

If the URL has no usable extension, the producer uses the sanitized lowercase
`resource_format` as a fallback:

```text
{resource_id}.{sanitized_resource_format_in_lowercase}
```

The resource identifier maximizes stability and prevents naming collisions.
The URL is preferred because it describes the file served by the source. The
format fallback preserves deterministic naming, but does not assert the true
file type; consumers must not use it as a content-type guarantee.

Human-readable source names and descriptions remain available in the catalog.
This policy does not resolve how changed remote content with an unchanged
`resource_id` should be versioned; that decision belongs to the pending raw-data
immutability and update policy.

## Timestamp policy

CKAN timestamps are stored after surrounding whitespace is removed and after
validating only that an optional value is a non-empty scalar string. Some CKAN
values do not declare a timezone, so converting them to UTC would add an
undocumented assumption. Any future temporal interpretation must define its
timezone policy explicitly and preserve the source value for audit.

## Download-eligibility policy

A resource is eligible for download only when both conditions hold:

1. `source_resource_state` equals `selection.required_resource_state` from
   `config/project.yml` after normalization.
2. `resource_format` equals `dataset.preferred_format` from
   `config/project.yml` after normalization.

Every discovered resource remains in the catalog. Resources that do not meet a
condition receive `eligible_for_download = FALSE` and a machine-readable
`eligibility_reason`:

- `eligible_preferred_format`
- `ineligible_non_active_source_state`
- `ineligible_missing_source_state`
- `ineligible_non_preferred_format`

State-related reasons take precedence over a format-related reason when both
conditions fail. Eligibility is a technical acquisition filter only. It must
not be interpreted as a decision that a resource is the canonical, complete or
non-overlapping epidemiological input for analysis.

## Version-control policy

`resources_catalog.csv` is versioned as provenance metadata. It records the
resource inventory used to make an acquisition decision at a point in time.
Operational logs and downloaded raw files are not versioned. A later provenance
manifest will identify the exact raw files used by the analysis.

## Compatibility

Changes to column names, meanings, types, requiredness or eligibility-reason
values require a new contract version and a documented migration decision.
Additive nullable columns are backward-compatible only after downstream
consumers explicitly tolerate them.
